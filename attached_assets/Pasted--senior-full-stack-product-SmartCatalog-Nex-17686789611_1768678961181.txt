9) Всё интуитивно понятно: пользователь видит прогресс настройки, подсказки и понятные переключатели.

C) ДАННЫЕ И PRISMA (МИГРАЦИИ)
========================
Добавь сущности (примерно; адаптируй под текущие модели):

1) AiSettings (1 на tenant)
- tenantId (unique)
- enabled (bool)
- language = "ru"
- tone: neutral|friendly|strict
- workingHoursJson (optional)
- fallbackHandoffText (RU)
- updatedAt

2) AiSalesScript (versioned)
- id
- tenantId
- version (int)
- title (например “Скрипт продаж v3”)
- stagesJson (5 этапов: цели, вопросы, критерии перехода)
- forbiddenPhrasesJson
- createdAt
- isActive (bool)

3) AiTagRule
- id
- tenantId
- tag (string) например “переведи_на_человека”
- displayName (RU)
- keywordsJson (массив фраз)
- priority (int)
- action: handoff|notify|send_catalog_link|stop_ai|none
- responseTemplate (RU, optional)
- isEnabled

4) AiKnowledgeArticle
- id
- tenantId
- title
- content (markdown)
- category (optional)
- isPublished
- updatedAt

5) AiFaqItem
- id
- tenantId
- question
- answer
- isPublished
- updatedAt

6) AiPolicy
- id
- tenantId
- policyJson (правила/ограничения, например “отвечать только из источников”)
- updatedAt

7) AiConversation
- id
- tenantId
- channel: sandbox|whatsapp|telegram|web
- visitorId/sessionId (optional)
- customerPhone (optional)
- status: open|handoff|closed
- createdAt, updatedAt

8) AiMessage
- id
- conversationId
- role: user|assistant|system|manager
- content
- tagMatched (optional)
- metaJson
- createdAt

9) AiInterventionEvent (для аналитики)
- id
- tenantId
- conversationId
- type: handoff_requested|no_answer|complaint|manual_takeover|tag_triggered
- tag (optional)
- createdAt

10) AiInboxTicket (внутренний “инбокс”)
- id
- tenantId
- conversationId (optional)
- title (RU)
- status: new|in_progress|done
- priority: low|normal|high
- note (optional)
- createdAt, updatedAt

Индексы: tenantId + createdAt, tenantId + isPublished, conversationId, type.

Это MUST HAVE для понятности.

  - “Подсказки менеджеру” (AI предлагает ответ, но требует кнопку “Отправить”)

- применять теги/триггеры (подсветить в UI: “Сработал тег: …”)
- если AI не нашёл ответа → создаётся AiInterventionEvent(type=no_answer) + тикет в Инбокс.

ВАЖНО: Реальный AI.
Используй текущий провайдер/модель проекта (если уже есть). Если в проекте ещё нет интеграции с LLM:
- добавь серверный слой /api/ai/respond, который вызывает LLM (например OpenAI через env OPENAI_API_KEY),
- но строго enforce policies: “answer only from sources”.
Если ключа нет — сделай graceful fallback: ассистент отвечает шаблоном “AI не настроен. Добавьте ключ в настройки” (но UI и хранение данных должны работать).

ПРОМПТИНГ (логика)
Ассистент получает:
- активный sales script (stagesJson)
- policies
- каталог (поиск top N релевантных товаров по запросу)
- активные акции/скидки
- faq + knowledge (поиск по тексту)
И отвечает ТОЛЬКО по этим данным.
Если данных недостаточно — задаёт уточняющие вопросы или предлагает менеджера.
Если сработал handoff тег — ассистент пишет:
“Понял. Сейчас подключу менеджера. Уточните, пожалуйста, ваш номер телефона/удобное время связи.”
