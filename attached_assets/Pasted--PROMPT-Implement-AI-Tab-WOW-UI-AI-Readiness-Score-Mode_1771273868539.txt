5) BACKEND API ENDPOINTS (EXPRESS)
==================================

All endpoints must read tenant_id from auth middleware and enforce it.

5.1 Score & readiness

* GET /api/ai/testing/score?period=...  (period optional; default “7d”)
  Returns:
  {
  scoreTotal: number,
  breakdown: {
  completeness: {score,max,items:{...}},
  behavior: {score,max,items:{...}},
  operations: {score,max,items:{...}},
  testing: {score,max,items:{...}},
  },
  lastComputedAt,
  notes: string[]
  }

* POST /api/ai/testing/score/recompute
  Recompute now.

* GET /api/ai/testing/readiness?goal=...
  Return READY/WARNING/BLOCKED + reasons + deep links

5.2 Testing chat

* POST /api/ai/testing/session/start { mode, personaKey? } -> { sessionId }
* POST /api/ai/testing/message/send { sessionId, userText } -> { assistantText, microEval }
* POST /api/ai/testing/message/feedback { messageId, action, editedText? }
  action enum:
  APPROVE | IMPROVE | TRAIN | FIX_ONLY | ADD_TO_KB | ANTI_PATTERN
  Store feedback into meta and (if TRAIN/ADD_TO_KB) forward to existing training/KB endpoints (reuse your current system).

5.3 Simulation

* POST /api/ai/testing/simulation/start { personaKey } -> starts a session + sends first simulated user message
* POST /api/ai/testing/simulation/next { sessionId } -> returns next simulated user message if needed (optional)
  (For MVP, simulation can just seed the first user message and then the user continues.)

5.4 Stress test

* POST /api/ai/testing/stress/run { scenarios?: string[] } -> { runId }
* GET /api/ai/testing/stress/run/:runId -> { status, progress, results }

6) “ГОТОВНОСТЬ AI-РОПа” SCORE MODEL (EXACT, IMPLEMENT THIS)
===========================================================

We need a score 0..100 that works even with low data.
Score must be explainable and computed from:
A) Configuration completeness
B) Sales behavior readiness
C) Operational readiness (payments/handovers/integrations)
D) Testing evidence (did we test and pass scenarios)

TOTAL SCORE = A + B + C + D

A) Completeness (0..30)

* Goal selected (5)
* Style selected (5)
* Objections configured count >= 4 (5)
* Handover rules configured (5)
* USP / positioning filled (5)
* Promotion strategy configured (segments/categories or manual) (5)

B) Behavior readiness (0..30)
Evaluate from rules/settings presence (not LLM quality yet):

* If goal = CLOSE_DEAL:

  * installments enabled OR payment flow configured (10)
  * “дорого” objection exists + response template exists (5)
  * upsell OR alternative-cheaper enabled (5)
* If goal = QUALIFY_HANDOVER:

  * handover triggers include “просит человека” + “нестандартный вопрос” (10)
  * lead capture fields defined (phone/name) OR CRM enabled (5)
* For any goal:

  * language(s) selected (5)
  * system prompt not empty OR using default template (5)

(Implement branching; if missing, score is 0 for that item.)

C) Operations readiness (0..20)

* Readiness check result:
  READY (20)
  WARNING (10)
  BLOCKED (0)
  This depends on:
* Payments configured if CLOSE_DEAL
* At least one outbound handover channel configured (internal CRM / Telegram / amo / Bitrix) if QUALIFY_HANDOVER
* Channel connection exists (WhatsApp) (required for any production usage) (if missing -> BLOCKED)

D) Testing evidence (0..20)

* Has at least 5 test messages exchanged in Testing tab in last 7d (5)
* Completed at least 1 simulation persona run (5)
* Completed stress test run (10) with pass rate:
  passRate >= 0.8 -> full 10
  0.5..0.79 -> 6
  <0.5 -> 2

PASS CRITERIA PER SCENARIO:

* assistant produced a helpful reply AND
* did not violate handover rules AND
* if objection scenario, it addressed it AND
* if CLOSE_DEAL, it offered payment path by end (or asked for confirmation step)

Return breakdown and notes.
Store snapshots to ai_score_snapshots.

7) MICRO EVALUATION AFTER EACH AI MESSAGE (0..10)
=================================================

After every assistant reply in Testing chat, return microEval:
{
score: 0..10,
positives: string[],
issues: string[],
suggestions: string[]
}

MVP heuristic evaluation (NO heavy NLP needed):

* +2 if reply mentions catalog item or asks clarifying question relevant to product
* +2 if matches selected style (short/friendly/premium) by length + greeting markers
* +2 if addresses selected objection keywords when user message contains them
* +2 if respects goal (e.g., offers payment for CLOSE_DEAL; offers handover when trigger)
* +2 if includes next-step CTA question

Deduct:

* -3 if hallucination markers (claims not in KB/catalog) (basic: if mentions “гарантия 3 года” when not in KB)
* -2 if too long in “short” mode
* -2 if ignores user question

8) CLIENT SIMULATION ALGORITHM (IMPLEMENT)
==========================================

Simulation mode is a “persona-driven” scripted user emulator.

8.1 Personas (define constants)
personaKey -> persona config:

* HAGGLER (“торгуется”)
* DOUBTER (“сомневаюсь”)
* COMPARER (“сравниваю с конкурентами”)
* CHEAPER (“хочу дешевле”)
* ANGRY (“агрессивный”)
* PREMIUM (“премиальный покупатель”)

Each persona has:

* opener messages (array)
* typical objections (array)
* behavior rules (when to escalate, when to ask discount, etc.)

8.2 Simulation flow
When user starts simulation:

1. Create ai_testing_session mode=SIMULATION personaKey
2. Choose an opener:

   * Try to pick a real product from catalog summary/top list
   * Example opener:
     “Здравствуйте. Сколько стоит <product_name>? Есть в наличии?”
3. Insert this opener as a user message (is_simulated=true)
4. Immediately call existing AI reply generator (same as Testing send) and return assistant message + microEval
5. Then continue as “guided”: user can either type manually OR click “Следующая реплика клиента”

   * Next simulated user message is chosen by:
     a) detect stage (offer/price/close) from last assistant reply (simple keywords)
     b) pick persona-specific next line:

     * HAGGLER: “А скидка есть?”, “Сделаете дешевле?”, “У конкурентов ниже”
     * DOUBTER: “Не уверен…”, “А гарантия?”, “Стоит ли переплачивать?”
     * COMPARER: “Почему у вас дороже чем X?”
     * CHEAPER: “Есть вариант подешевле?”
     * ANGRY: “Почему так дорого?”, “Вы вообще отвечаете нормально?”
     * PREMIUM: “Нужна лучшая модель. Что порекомендуете?”
6. Stop after 6–10 turns OR when AI reaches goal end state:

   * CLOSE_DEAL: payment link offered + user confirmed
   * QUALIFY: collected lead + handover triggered
     Return a session summary at the end:

* closed? yes/no
* reason if no
* recommendation (auto)

Store scenario results into ai_testing_messages.meta.

9) STRESS TEST ALGORITHM (IMPLEMENT)
====================================

Stress test runs 10 scenarios quickly and outputs pass rate + weak points.

9.1 Scenario set (default 10)

* PRICE_HIGH: “Дорого”
* ASK_DISCOUNT: “Есть скидка?”
* WANT_CHEAPER: “Хочу дешевле”
* COMPARE: “У конкурентов дешевле”
* INSTALLMENT: “Есть рассрочка?”
* WARRANTY: “Какая гарантия?”
* DELIVERY: “Как доставка/самовывоз?”
* HUMAN: “Дайте менеджера”
* COMPLEX: “Нестандартный вопрос…” (force handover if rule)
* CLOSE: “Готов купить, как оплатить?”

9.2 Execution
For each scenario:

* Start a fresh hidden testing session (mode=STRESS_TEST)
* Send the scenario user message
* Get assistant reply
* Evaluate pass/fail using PASS CRITERIA from section 6D
* Record:
  {scenarioKey, userText, assistantText, pass, issues[], suggestion[]}

After run:

* compute passRate
* store to ai_stress_test_runs
* update score snapshot (Testing evidence part)

Frontend:

* show progress bar 0..100%
* show results table with pass/fail badges
* allow click a row to open a replay modal (WhatsApp view)
