0) DEFINITIONS (CRITICAL)
=========================

AI-РОП supports multiple “Goals” (selected in Strategy):

* CLOSE_DEAL (Закрывать сделки) — AI leads to payment
* QUALIFY_HANDOVER (Квалификация + передача) — AI collects info + hands to manager
* CONSULT_PICK (Консультация + подбор) — AI helps choose and moves to next step (order/lead)
* ORDER_NO_PAY (Заказ без оплаты) — AI forms order, payment later

Analytics success must be computed differently per goal.

A “Dialog” is a conversation thread with messages and timestamps.
We must store outcomes and derived metrics per dialog:

* stage timeline (funnel stages)
* objections encountered
* handover occurred (and why)
* catalog interactions (if product suggested/selected)
* payment link offered (if applicable)
* payment confirmed (if you can detect)
* drop-off point (where user stopped responding)

3) FUNNEL STAGES + EVENT EXTRACTION (EXACT)
===========================================

We need consistent stages:

Stages enum (ai_funnel_stage):

1. GREETING (старт/приветствие)
2. NEEDS (выявление потребности)
3. OFFER (предложение товара/варианта)
4. OBJECTION (обработка возражений)
5. CLOSE (закрытие на следующий шаг: оплата/заказ/контакт)
6. SUCCESS (цель достигнута)
7. HANDOVER (передано менеджеру)
8. DROP (клиент пропал/отказ)

Event extraction (MVP heuristic; no heavy NLP):
Given messages sequence, compute stage timeline:

* GREETING: first assistant response exists
* NEEDS: assistant asks clarifying questions about need OR user describes need (keywords: "нужно", "ищу", "хочу", model/size/color)
* OFFER: assistant suggests product(s) OR mentions SKU/name/price (detect catalog mention or pattern “₸/тг/тенге”)
* OBJECTION: user message contains objection keywords (see list below)
* CLOSE: assistant asks for order confirmation / offers payment / asks contact / proposes next step ("оформим", "оплатить", "оставьте номер", "подтвердите")
* SUCCESS/HANDOVER/PAYMENT_CONFIRMED/ORDER_CREATED based on events below
* DROP if no user response after last assistant message within threshold (default 24h for production, 30m for testing)

Objection keyword map (store as constants; editable later):

* PRICE: "дорого", "цена", "скидк", "дешевле", "дороговато"
* COMPARE: "конкурент", "у других", "сравниваю", "в другом месте"
* TRUST: "гарант", "оригинал", "поддел", "сертификат", "отзывы"
* DELIVERY: "доставка", "самовывоз", "когда привез", "срок"
* PAYMENT: "оплата", "kaspi", "рассроч", "перевод"
* STOCK: "в наличии", "есть?", "нет?", "под заказ"
* OTHER: fallback

Detect events:

* HANDOVER_TRIGGERED: if assistant says handing to manager OR system recorded handover
* PAYMENT_OFFERED: assistant includes payment instruction/link phrase ("ссылка", "Kaspi Pay", "оплатить")
* PAYMENT_CONFIRMED: if your system has payment webhook => record; else allow manual marking (optional later)
* ORDER_CREATED: if internal order object created (if exists)
* LEAD_CAPTURED: if assistant asks and user provided phone/name (regex phone)

Store events in ai_dialog_events and update ai_dialogs fields.

4) SUCCESS MODEL (EXACT, PER GOAL)
==================================

Compute outcome for each dialog:

If goal = CLOSE_DEAL:

* SUCCESS if PAYMENT_CONFIRMED exists OR (ORDER_CREATED + PAYMENT_OFFERED + user confirmation like “оплатил/оплатила/готов оплатить”)
* HANDOVER if handover triggered
* ABANDONED if DROP and no success/handover
* FAILED if user explicit отказ ("не надо", "передумал", "неинтересно")

If goal = QUALIFY_HANDOVER:

* SUCCESS if HANDOVER_TRIGGERED AND lead_captured=true (name/phone) OR CRM lead created event exists
* HANDOVER if triggered but lead not captured (count as partially successful for KPI)
* ABANDONED if DROP before lead capture
* FAILED if explicit refusal

If goal = CONSULT_PICK:

* SUCCESS if PRODUCT_SELECTED OR user indicates intent ("беру", "давайте этот", "оформляем") OR lead captured
* ABANDONED/DROP similar

If goal = ORDER_NO_PAY:

* SUCCESS if ORDER_CREATED OR user confirmed order details + next step agreed
* HANDOVER if handed to manager

KPIs must show both:

* SuccessRate (strict)
* AssistedSuccessRate (success + handover, depending on goal)

6) FUNNEL + BOTTLENECK LOGIC (EXACT)
====================================

Funnel counts:
For each dialog, derive max stage reached and stage transitions.
Compute:

* # dialogs entering each stage
* Conversion between stages (%)

Bottleneck detection:
Define “dropoff stage” as the stage after which user stopped responding OR explicit refusal occurred.
Compute dropoff distribution by stage.
Primary bottleneck = stage with highest (dropoffs / dialogs_entered_stage) with minimum sample size >= 10 (or >=3 for testing).

Also compute bottleneck by:

* category (if product/category known)
* price segment (below avg, avg..1.3x, >1.3x)
* channel
  Return top 3 bottlenecks with evidence.

12) AUTO-AUDIT (THE MOST IMPORTANT PART)
========================================

User clicks “Запустить аудит”.

Audit flow:

* Create ai_audit_runs status=RUNNING
* Analyze last N dialogs in period (default N=50, cap 200)
* Compute:

  * KPIs summary
  * bottlenecks
  * missing config checks
  * missing KB checks
  * missing trigger suggestions
  * “handover too early” flags
* Write findings to ai_audit_findings with:
  severity, type, title, details, suggested_fix (deep link + optional payload), evidence (dialog_ids + sample messages)
* Mark DONE

Audit recommendations MUST be actionable and lead to:

* Strategy (enable installments, add USP, adjust handover)
* Training (create trigger, add KB, add anti-pattern)
* Testing (run stress test)

Suggested fixes structure:
suggested_fix = {
deepLink: "/app/ai-rop/strategy#installments",
action: "ENABLE_INSTALLMENTS",
payload: { banksSuggested: ["Kaspi","Halyk Bank"] }
}

Audit examples (create findings):
HIGH:

* “Низкая конверсия на этапе цены” with evidence
* “Цель CLOSE_DEAL, но оплаты не настроены” (BLOCKER)
  MEDIUM:
* “Часто передаёте менеджеру слишком рано”
  LOW:
* “Редко используете промо-зону”
