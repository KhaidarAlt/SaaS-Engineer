# PROMPT: Rebuild “Интеграции” as a unified premium Control Center for all channels (WOW UX) + WAHA risk disclaimer gating + Meta dedicated space

Stack: React 18 + TypeScript (Vite), Tailwind, Framer Motion. Backend: Express + Postgres. Multi-tenant.

GOAL:
Create ONE place where user connects all communication channels for AI (and sees health/status). Current integrations are scattered (WAHA, WhatsApp Meta page, Instagram, Telegram, website widget). Unify under:

* /app/integrations (single entry)
* keep dedicated “WhatsApp Meta” subspace (complex)
* include WOW onboarding wizards for each channel
* include hard WAHA disclaimer gating with “I read & agree” checkbox before enabling Connect.

CRITICAL:

* Multi-tenant: tenant_id required in all DB reads/writes.
* Do not break existing WhatsApp Meta pages; re-route entry to them from unified page.
* UX must be premium, calm, Apple-like, with micro-interactions and clear statuses.
* Provide safe, policy-compliant guidance: WAHA disclaimer focuses on compliance best practices and warns about possible bans; do NOT provide instructions for evading WhatsApp enforcement or spam tactics.

3) DATA MODEL (POSTGRES)
========================

Table: integrations

* id uuid pk
* tenant_id uuid index
* type enum: WHATSAPP_META | WHATSAPP_WAHA | INSTAGRAM_DIRECT | TELEGRAM_BOT | WEB_WIDGET
* status enum: NOT_CONNECTED | CONNECTING | CONNECTED | ERROR | NEEDS_ACTION
* display_name text (e.g., “WhatsApp +7 777 …”)
* is_ai_enabled boolean default true
* last_checked_at timestamptz
* last_error text nullable
* config jsonb (channel-specific secrets/ids, masked where appropriate)
* created_at, updated_at

Table: integration_events

* id uuid pk
* tenant_id uuid index
* integration_id uuid fk
* event_type text (CONNECTED, DISCONNECTED, ERROR, WEBHOOK_TESTED, TOKEN_REFRESHED)
* message text
* meta jsonb
* created_at timestamptz

Table: waha_disclaimer_acceptance

* id uuid pk
* tenant_id uuid unique
* accepted boolean
* accepted_at timestamptz
* accepted_ip text nullable
* accepted_user_id uuid nullable
* version text (e.g. "2026-02-17-v1")
  Store acceptance required before WAHA connect.

6) WAHA WIZARD: /app/integrations/whatsapp/waha
===============================================

MUST INCLUDE DISCLAIMER GATING before showing QR.

Step 0: Compliance warning (blocking)
Title: “Перед подключением WAHA — важно”
Content: show a clear, short, non-technical warning list (see below).
At bottom:
☐ “Я прочитал(а) и согласен(на) с условиями. Понимаю риски блокировки номера и что ответственность лежит на владельце номера.”
Button “Продолжить” disabled until checked.
On confirm:
POST /api/integrations/waha/accept-disclaimer { version }
Store acceptance in waha_disclaimer_acceptance for tenant.

DISCLAIMER TEXT (MVP, must be displayed):

* WAHA использует неофициальное подключение. WhatsApp может ограничить/заблокировать номер за нарушения правил.
* Запрещено: массовые рассылки без согласия, спам, однотипные сообщения большому числу людей, покупные базы, агрессивные авто-сообщения.
* Рекомендуется: отвечать на входящие запросы, получать явное согласие клиента, соблюдать частоту, использовать корректные шаблоны общения, быстро обрабатывать жалобы и стоп-слова.
* Если нужен максимально безопасный вариант — используйте официальный Meta канал.

Step 1: Connect QR

* Show QR code card with “Сканируйте QR в WhatsApp”
* Live status: “Ожидаем сканирование…”
* After scan: “Сессия активна”
  POST /api/integrations/waha/connect/start -> returns sessionId + qr
  Poll /api/integrations/waha/connect/status?sessionId

Step 2: Assign number & AI

* Choose what this WAHA number is used for:

  * ☑ Заказы из каталога
  * ☑ AI ответы клиентам
* Save to integrations table is_ai_enabled, display_name.

Step 3: Test

* “Отправить тестовое сообщение” -> sends to owner’s number OR internal testing
* Show success checkmark + confetti micro animation (subtle).
