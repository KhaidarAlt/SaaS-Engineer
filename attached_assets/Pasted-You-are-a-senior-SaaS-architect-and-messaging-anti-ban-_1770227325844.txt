You are a senior SaaS architect and messaging anti-ban engineer.

Build a Safe Bulk Messaging Engine for WhatsApp
inside a SaaS platform called “SmartCatalog”.

WhatsApp connection is implemented via WAHA.
Cloud API is NOT used.

The goal:
Enable sending messages to a large client base
WITHOUT mass-spam behavior and WITHOUT number bans.

INTERFACE LANGUAGE: RUSSIAN ONLY

────────────────────────────────
CORE PHILOSOPHY
────────────────────────────────
1. This is NOT a “рассылка”
2. This is a context-based conversation reactivation system
3. Every message must look like a natural continuation of dialog
4. Safety > volume
5. System must self-regulate message limits

────────────────────────────────
NEW MODULE
────────────────────────────────
Create a new module:
📌 **“Умный повторный контакт”**

NOT named:
- Рассылки
- Массовые сообщения
- Маркетинг

────────────────────────────────
ELIGIBLE CONTACTS (VERY IMPORTANT)
────────────────────────────────
Messages can be sent ONLY if:
- Client previously wrote at least one message
- Client was not blocked
- Client did not send “стоп”
- Client did not reply in last N hours

Store flags:
- has_dialog_history
- do_not_disturb
- last_client_reply_at

────────────────────────────────
MESSAGE TRIGGERS
────────────────────────────────
Allowed triggers only:

1. Abandoned cart
2. Unpaid order
3. Previous purchase (reactivation)
4. Long inactivity after dialog
5. Manual trigger by business user

NO cold outreach.

────────────────────────────────
SAFE VOLUME LIMITS (DYNAMIC)
────────────────────────────────
System must NOT use fixed limits.

Implement dynamic rate control based on:
- reply_rate (% of replies)
- ignore_rate
- block_rate (if detectable)
- delivery errors

Rules:
- If reply_rate drops → decrease volume
- If replies are high → slowly increase volume
- Hard safety cap per number: ~1000 messages/day
- Batch sending with random delays
- No burst sending

────────────────────────────────
AUTO RATE-LIMIT ENGINE
────────────────────────────────
Create a limiter that:
- Calculates allowed messages per hour
- Randomizes delays
- Spreads sending across time
- Stops instantly if negative signals detected

Limiter must work via message queue.

────────────────────────────────
AI MESSAGE GENERATION
────────────────────────────────
AI must:
- Generate UNIQUE messages per client
- Use dialog context (products, orders, payments)
- Ask a question to provoke reply
- Avoid sales pressure
- Use polite human tone

Language: Russian only

Examples (conceptual):
- Reminder
- Clarification
- Help offer
- Soft reactivation

DO NOT repeat same text.

────────────────────────────────
QUIET HOURS
────────────────────────────────
Implement quiet hours:
- Default: 22:00 – 09:00
- Configurable per account
- No messages sent during quiet hours

────────────────────────────────
ANTI-SPAM RULES
────────────────────────────────
- Max follow-ups per client: configurable
- Cancel scheduled message if client replies
- One active message per dialog at a time
- Immediate stop if “стоп”, “не пишите”, etc.
