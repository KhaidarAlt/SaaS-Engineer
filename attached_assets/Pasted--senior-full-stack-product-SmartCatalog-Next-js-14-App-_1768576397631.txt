ЧАСТЬ 1 — СОБЫТИЯ (EVENT TRACKING)
Внедри трекинг следующих событий на витрине (публичный каталог):
- catalog_view (открыли каталог)
- product_view (открыли страницу товара)

ТРЕБОВАНИЯ К EVENT DATA
Каждый event должен иметь:
- id (uuid)
- tenant_id
- created_at
- event_type (enum/string)
- session_id (cookie) — генерируй на клиенте и храни в cookie (например sc_sid)
- visitor_id (cookie) — отдельный cookie для “уникальности” (например sc_vid)
- page_path
- referrer (если доступно)
- utm_source, utm_medium, utm_campaign, utm_content, utm_term (если присутствуют в URL)
- object_type + object_id (например product / productId, order / orderId)
- metadata_json (например: qty, variantId, price, query)

СОХРАНЕНИЕ В БД
Сделай API endpoint /api/events/track, который принимает событие и записывает в БД.
Важно: это публичный endpoint, но он должен:
- принимать tenantSlug и резолвить tenant_id безопасно
- rate limit по session_id (простая защита)
- не принимать произвольные event_type (валидация whitelist)
- не позволять писать события в чужой tenant (проверка по slug)

ЧАСТЬ 2 — КОРЗИНА И “БРОШЕННЫЕ КОРЗИНЫ”
Сделай сущность cart_session, чтобы можно было считать abandoned carts.
Требования:
- Каждый посетитель/сессия имеет cart_session (tenant_id + session_id).
- cart_session хранит:
  - status: active | converted | abandoned | expired
  - cart_json (позиции: productId/variantId/name/qty/price)
  - last_activity_at
  - first_seen_at
  - checkout_phone (если пользователь ввёл телефон на чек-ауте до создания заказа)
  - total_estimated
- При add_to_cart / remove_from_cart / qty_change обновляй cart_session (last_activity + total_estimated + cart_json).
- При order_created:
  - пометь cart_session как converted и привяжи order_id.
- Планировщик (cron) раз в 30 минут:
  - помечает cart_session как abandoned, если:
    status=active AND last_activity_at < now - thresholdHours (по умолчанию 24 часа)
  - threshold должен быть настраиваемым в tenant settings (например abandoned_cart_hours).

ЧАСТЬ 4 — РАСЧЁТ МЕТРИК (формулы)
Определения:
- visits_total = count(catalog_view)
- visits_unique = count(distinct visitor_id) WHERE event_type=catalog_view
- add_to_cart = count(add_to_cart)
- carts_unique = count(distinct session_id) WHERE event_type=add_to_cart
- checkout_start = count(checkout_start)
- orders_created = count(order_created) OR count(orders) по createdAt (согласуй, чтобы совпадало)
- whatsapp_clicked = count(whatsapp_open_clicked)
- revenue = sum(order.total) за период (только статусы не cancelled)
- avg_check = revenue / orders_created
- abandoned_carts = count(cart_session where status=abandoned and last_activity within period window or became abandoned within period)
- CR_order = orders_created / visits_unique * 100
- CR_cart = carts_unique / visits_unique * 100
- CR_whatsapp = whatsapp_clicked / orders_created * 100

Сравнение периодов:
- Для каждого KPI показывай % изменения vs previous period with same length.
