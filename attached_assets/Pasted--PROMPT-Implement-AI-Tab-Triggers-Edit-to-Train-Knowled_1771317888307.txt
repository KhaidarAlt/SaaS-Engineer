5) DATABASE (POSTGRES, TENANT-SCOPED)
=====================================

5.1 ai_triggers

* id uuid pk
* tenant_id uuid indexed
* is_enabled bool default true
* priority int default 100 (lower = higher priority)
* match_type enum: KEYWORD | REGEX | INTENT
* match_value text               // e.g. "дорого" or regex
* conditions jsonb nullable      // optional conditions (goal, category, price range)
* action_type enum:
  ADD_LINE_TO_REPLY |
  FORCE_HANDOVER |
  OFFER_INSTALLMENT |
  OFFER_CHEAPER |
  UPSELL |
  APPLY_PROMO |
  ASK_CLARIFYING_QUESTION |
  USE_SCRIPT_SNIPPET
* action_payload jsonb           // e.g. {text:"...", bank:"Kaspi"} or {question:"..."}
* created_at timestamptz
* updated_at timestamptz

5.2 ai_knowledge_items

* id uuid pk
* tenant_id uuid indexed
* type enum:
  DELIVERY | PAYMENT | INSTALLMENTS | WARRANTY | RETURNS | STORE_INFO | USP | BRAND | PRODUCT_RULE | OTHER
* title text
* content text
* source enum: USER | IMPORT | TRAINING | SYSTEM
* tags text[] nullable
* is_active bool default true
* created_at timestamptz
* updated_at timestamptz

5.3 ai_training_events

* id uuid pk
* tenant_id uuid indexed
* event_type enum:
  EDIT_REPLY |
  TRAIN_APPROVED |
  KB_ADDED |
  TRIGGER_CREATED |
  TRIGGER_UPDATED |
  ANTI_PATTERN_ADDED |
  IGNORE_SUGGESTION
* ref_id uuid nullable (points to message/trigger/kb item)
* context jsonb (store: userText, oldReply, newReply, mode, personaKey, scenarioKey)
* created_at timestamptz

5.4 ai_anti_patterns

* id uuid pk
* tenant_id uuid indexed
* pattern_type enum: KEYWORD | REGEX | CLAIM
* pattern_value text
* note text nullable
* is_active bool default true
* created_at timestamptz

6) BACKEND API ENDPOINTS (EXPRESS)
==================================

All tenant-scoped.

6.1 Quick train from edited messages

* POST /api/ai/training/quick-train
  Body:
  {
  userText: string,
  assistantText: string,
  editedText: string,
  applyMode: "FIX_ONLY" | "TRAIN_FUTURE" | "ADD_TO_KB" | "ANTI_PATTERN",
  meta?: { goal?, scenarioKey?, personaKey?, productId? }
  }
  Behavior:
* FIX_ONLY: save training event only (no global change)
* TRAIN_FUTURE: create a trigger (INTENT or KEYWORD) automatically + store as event
* ADD_TO_KB: create knowledge item (type guessed) + store as event
* ANTI_PATTERN: create anti-pattern based on wrong claim patterns + store as event
  Return:
  { ok: true, createdTriggerId?, createdKnowledgeId?, createdAntiPatternId? }

6.2 Triggers CRUD

* GET  /api/ai/triggers
* POST /api/ai/triggers
* PUT  /api/ai/triggers/:id
* DELETE /api/ai/triggers/:id
* POST /api/ai/triggers/:id/toggle (enable/disable)

6.3 Knowledge CRUD

* GET  /api/ai/knowledge
* POST /api/ai/knowledge
* PUT  /api/ai/knowledge/:id
* DELETE /api/ai/knowledge/:id
* POST /api/ai/knowledge/import-from-catalog
  -> auto-generate knowledge items from existing store settings + catalog (delivery/payment/store info/USP if exists)

6.4 Anti-patterns CRUD

* GET  /api/ai/anti-patterns
* POST /api/ai/anti-patterns
* PUT  /api/ai/anti-patterns/:id
* DELETE /api/ai/anti-patterns/:id
* POST /api/ai/anti-patterns/:id/toggle

6.5 History

* GET /api/ai/training/history?limit=50&offset=0

8) HOW TRIGGERS & KB AFFECT AI (INFERENCE LOGIC)
================================================

You must integrate triggers and KB into the AI reply generation pipeline used in:

* Testing tab message/send
* (later production chats)

MVP approach (deterministic):
When generating assistant reply:

1. Retrieve active triggers ordered by priority
2. For each trigger:

   * if match_type=KEYWORD and userText includes match_value (case-insensitive) -> match
   * REGEX -> test regex
   * INTENT -> treat as keyword for MVP
   * if conditions exist, validate (goal/category/price range if identifiable)
3. Collect matched triggers (limit 3)
4. Apply actions:

   * ADD_LINE_TO_REPLY: append/inject snippet at end or after first sentence
   * FORCE_HANDOVER: return handover directive (or add “Сейчас подключу менеджера…”)
   * OFFER_INSTALLMENT: mention installments banks from knowledge/settings
   * OFFER_CHEAPER: instruct product selector to prioritize ENTRY items
   * UPSELL: suggest higher-tier item if relevant
   * APPLY_PROMO: reference promo-zone items
   * ASK_CLARIFYING_QUESTION: add a question
   * USE_SCRIPT_SNIPPET: insert snippet from action_payload
5. Retrieve relevant knowledge items (simple keyword search by tags/type) and include as “facts” context
6. Anti-patterns: before sending, scan reply:

   * if contains forbidden keyword/regex -> remove offending sentence and add safe alternative (“Уточню и вернусь”)
     Log a training event if anti-pattern was prevented (optional).

No hallucination: If knowledge does not confirm warranty/delivery, AI must ask clarifying questions instead.
